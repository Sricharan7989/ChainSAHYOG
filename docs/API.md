# API Specification & Payload Structures

This document provides exhaustive data schemas and JSON specifications for all API responses generated by the ChainSAHYOG engine.

---

## 1. Trace Endpoint: `GET /trace`

### Request Parameters (Query String)
```http
GET /trace?address=0x62425cd6bdcb6bfe51558ea465b063486b70dc9f&chain_id=1&max_depth=3&dust_threshold=0.001&mode=auto&save=false
```

| Field | Type | Description |
| :--- | :---: | :--- |
| `address` | `string` | **Required**. Suspect EVM address (40 hex chars prefixed with `0x`). |
| `chain_id` | `integer` | Chain ID (`1` Ethereum, `137` Polygon, `56` BNB, `42161` Arbitrum). Default: `1`. |
| `max_depth` | `integer` | Maximum forward BFS hops (`1` to `6`). Default: `4`. |
| `dust_threshold` | `float` | Minimum native transfer amount to follow. Default: `0.001`. |
| `mode` | `string` | Execution mode: `auto` (default), `live`, or `cache`. |
| `save` | `boolean` | Save result to replay cache if `true` and fetched live. Default: `false`. |

## 2. Cytoscape.js Element Compatibility

The arrays in `nodes` and `edges` are serialized specifically for direct consumption by Cytoscape.js:

### Node Data Properties
- `id`: Lowercased hexadecimal Ethereum address.
- `depth`: Network hop distance from start wallet (`0` for suspect wallet).
- `is_start`: Boolean indicating whether this is the investigator's initial query address.
- `label`: Name of institution (e.g. `"Binance"`, `"Tornado.Cash"`) or `null` for anonymous wallets.
- `entity_type`: Classification: `"exchange"`, `"suspected_exchange"`, `"mixer"`, `"bridge"`, `"sanctioned"`, or `null`.
- `is_vasp`: Boolean (`true` for confirmed or suspected exchanges).
- `is_mixer`: Boolean (`true` for obfuscation mixers).
- `is_bridge`: Boolean (`true` for cross-chain bridges).
- `tainted_in`: Key-value map of assets (`{symbol: amount}`) attributable to the suspect that entered this node.

### Edge Data Properties
- `source`: Sender address (`id` of source node).
- `target`: Recipient address (`id` of target node).
- `assets`: List of all distinct tokens transferred along this edge, including `asset`, `contract`, `decimals`, `value`, `tainted_value`, `tainted_fraction`, and `tx_hash`.
- `value`: Primary asset amount (used for visual edge thickness).
- `value_eth`: Native token amount for backwards compatibility.
- `tx_hash`: Representative transaction hash on public explorer.
- `depth`: BFS walk depth at which this transfer was discovered.

## 3. Error Response Format (RFC 7807)

FastAPI returns standardized JSON error responses for all non-200 outcomes:

```json
{
  "detail": "Human-readable explanation of failure"
}
```

### Common Error Catalog

| Status Code | Reason | Example Response |
| :---: | :--- | :--- |
| **`400 Bad Request`** | Malformed EVM Address | `{"detail": "'0x123' is not a valid EVM address (expected 0x + 40 hex chars)."}` |
| **`404 Not Found`** | Cache Miss on Replay | `{"detail": "No recorded trace for 0x624... on Ethereum. Run it live first, or use mode=auto."}` |
| **`422 Unprocessable`** | Unsupported Chain | `{"detail": "Unsupported chain id 999. Supported: 1 (Ethereum), 137 (Polygon), 56 (BNB Chain), 42161 (Arbitrum One)"}` |
| **`502 Bad Gateway`** | Etherscan API Failure | `{"detail": "Etherscan returned status 0: Max rate limit reached"}` |
| **`503 Service Unavail`** | Missing API Credentials | `{"detail": "ETHERSCAN_API_KEY is not configured in backend/.env - cannot run a live trace."}` |
