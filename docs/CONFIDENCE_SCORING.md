# Explainable Confidence Scoring

This document details the explainable, additive confidence scoring algorithm implemented in `backend/core/scoring.py`.

---

## 1. Design Philosophy: Explainable Arithmetic vs Machine Learning

Attribution findings generated by ChainSAHYOG can justify legal search warrants, freeze orders, and lawful KYC data disclosures against real individuals.

### Why Machine Learning Is Rejected for Attribution Scoring
If a deep neural network or random forest classifier emits an attribution score of `0.87`:
- It cannot explain *why* it arrived at 0.87.
- A defense attorney will successfully argue that the model is an unverified black box.
- A magistrate or judge cannot evaluate which specific on-chain facts established probable cause.

**ChainSAHYOG uses a deterministic, transparent weighted-point arithmetic system.** Every single point added or deducted is tied directly to a documented on-chain measurement. The API response and the PDF report print the full arithmetic breakdown, enabling investigators and defense counsel to interrogate every term.

---

## 2. The Three Scoring Factors

The confidence score is computed as the bounded sum of three primary factors:

$$\text{Confidence Score} = \text{Clamp}_{5}^{95}\Big(\text{Method Points} + \text{Distance Points} + \text{Path Cleanliness Points}\Big)$$

```
┌─────────────────────────────────────────────────────────────┐
│  Method Points       │  Known Label (+50) or Heuristic (+22) │
│  Distance Points     │  Hop 1 (+30) with -7 per hop decay   │
│  Path Cleanliness    │  Clean (+15), Mixer (-30), Bridge (-12)│
│  ─────────────────── │  ─────────────────────────────────── │
│  Final Score         │  Clamped strictly between 5% and 95% │
└─────────────────────────────────────────────────────────────┘
```

---

### Factor 1: Identification Method (`core/identify.py`)
Measures the reliability of how the destination entity was recognized:

| Identification Method | Score Contribution | Rationale |
| :--- | :---: | :--- |
| **`known_label`** | **+50 points** | Verified public registry match (Etherscan, TagPacks, OFAC). |
| **`consolidation`** | **+22 points** | Algorithmic fan-in heuristic. Lower baseline because criminal re-pooling shares the same topology. |
| *Default / Unknown* | **0 points** | Unidentified destination. |

---

### Factor 2: Hop Distance (`hop_distance`)
Measures network proximity from the suspect wallet. Shorter paths retain higher evidential weight:

| Hop Distance | Points Calculation | Score Contribution |
| :---: | :---: | :---: |
| **1 Hop** | $30 - (0 \times 7)$ | **+30 points** |
| **2 Hops** | $30 - (1 \times 7)$ | **+23 points** |
| **3 Hops** | $30 - (2 \times 7)$ | **+16 points** |
| **4 Hops** | $30 - (3 \times 7)$ | **+9 points** |
| **5 Hops** | $30 - (4 \times 7)$ | **+2 points** |
| **$\ge 6$ Hops** | $30 - (5 \times 7)$ | **0 points** (floor) |

---

### Factor 3: Path Cleanliness
Evaluates obfuscation infrastructure crossed by funds between the suspect and the destination:

| Path Condition | Score Adjustment | Rationale |
| :--- | :---: | :--- |
| **Clean Path** | **+15 points** | No mixers or bridges crossed along the transfer trail. |
| **Mixer Crossed** | **−30 points** | Funds traversed a mixer (e.g. Tornado Cash). On-chain link severely impaired. |
| **Bridge Crossed** | **−12 points** | Funds crossed an L2 or cross-chain bridge. Custody continuity weakened. |

---

## 3. Score Clamping & Boundaries

After summing the three factors, the score is strictly clamped:

$$\text{Final Score} = \max\Big(5, \min(95, \text{Raw Score})\Big)$$

### The 95% Ceiling Rule
**No attribution score ever exceeds 95%.**
- *Rationale*: Exchanges periodically rotate hot wallets, labels can experience latency, and unexpected smart contract delegate calls can occur. A software tool that claims "100% certainty" in a criminal proceeding invites investigative negligence and will be scrutinized by courts.

### The 5% Floor Rule
**Any identified entity retains at least 5% confidence.**
- *Rationale*: Even if a trail crosses a mixer and spans 5 hops, reaching a verified exchange wallet remains an evidentiary lead that should not be rounded to absolute zero.

## 4. Scoring Example Comparisons

### Scenario A: High-Confidence Direct Deposit
- **Entity**: Binance (Direct Label Match $\to$ `+50`)
- **Distance**: 2 Hops from suspect (`+23`)
- **Path**: Clean direct transfer (`+15`)
- **Arithmetic**: $50 + 23 + 15 = 88$ points.
- **Reported Score**: **88% Confidence**.

### Scenario B: Unconfirmed Lead Across a Bridge
- **Entity**: Suspected Hub (Consolidation Heuristic $\to$ `+22`)
- **Distance**: 3 Hops from suspect (`+16`)
- **Path**: Crossed Arbitrum Bridge (`-12`)
- **Arithmetic**: $22 + 16 - 12 = 26$ points.
- **Reported Score**: **26% Confidence**.

## 5. Auditability Representation

Every attribution object includes:
- `confidence_score`: Integer percentage (`5` to `95`).
- `confidence_breakdown`: Single-line summary (e.g. `"direct label match (+50), 2 hops from suspect (+23), clean path (+15)"`).
- `confidence_components`: Machine-readable array of objects `{ name, points, reason }` enabling frontends and PDF generators to render tabular score breakdowns.
